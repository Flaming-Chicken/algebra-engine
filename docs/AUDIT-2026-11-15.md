# URAE audit — 15 Nov 2026

> [!NOTE]
> **Reconciliation Update (Latest Audit)**: This historical snapshot audited commit `23f508b`. Subsequent updates resolved several critical defects noted below (e.g., precedence-aware formatter grouping, selected executor matrix/calculus arms, reference oracle test fixtures in `tests/tests/engine/reference_oracle_tests.rs`, and `tests/tests/engine/audit_regression_tests.rs`), while other structural placeholders and oversimplifications remain open. For the current codebase audit and remediation roadmap, see [CODEBASE_AUDIT_AND_REMEDIATION_PLAN.md](CODEBASE_AUDIT_AND_REMEDIATION_PLAN.md).

Audited commit `23f508b` on `dev` (the overhaul: cat-core 4-fidelity eval, BSGS
tensor canonicalisation, generalized transforms, polyglot DSL), version 0.3.2.

**Verdict (at `23f508b`).** URAE has a sound foundation (arena DAG, exact big-integer
combinatorics, a fast runtime, many front ends) but at the audited commit its
core computer-algebra behaviour returned wrong answers for common
calculus, solving and factoring inputs, printed expressions without
parentheses, and reported success for about a dozen commands that computed
nothing. The 675 passing tests at that revision did not exercise these paths.

## How this was checked

- `cargo test --workspace --exclude urae-py`: **675 passed, 0 failed** (at `23f508b`).
- A release build of `urae-cli` was driven with about 230 known-answer
  inputs through the REPL and the `--json` API.
- The executor, simplifier, differentiator, formatter and number-theory code
  were read to confirm the cause of each failure.
- Not checked at that revision: the notebook GUI, WASM, LSP, Python and C bindings,
  GPU code, and the physics/advanced modules beyond what the executor exposes.

## 1. Correctness

### 1.1 The printer drops parentheses (highest priority)

`crates/algebra-core/src/format.rs` joins `Add` terms with `+` and `Mul`
factors with `·` and never adds parentheses. All three formatters (Unicode,
LaTeX, the third at line 550) do this, so every interface is affected.

| Input | Printed | Should be |
|---|---|---|
| `expand (x + 1)^5` | `x + 1^5` | `(x + 1)^5` (and it isn't expanded) |
| `factor x^2 - 5*x + 6` | `x + -3 · x + -2` | `(x - 3)(x - 2)` |
| `(a+b)/(c-d)^2` (Unicode) | `(a + b) / (c + -d^2)` | `(a + b)/(c - d)^2` |
| `simplify (x^a)^b` | `x^a^b` | `(x^a)^b` |
| `solve x^2 - 2 = 0` | `2^1/2` | `2^(1/2)` |

Many results that look wrong are correct underneath (the factorisation above
is right), but no output can be trusted or pasted back in. Also,
subtraction prints as `+ -`, and an unresolvable symbol silently prints as
`x` (`format.rs:57`).

### 1.2 Wrong answers

| Input | URAE | Correct |
|---|---|---|
| `diff 2^x, x` and `diff a^x, x` | `0` | `2^x ln 2`, `a^x ln a` |
| `diff x^x, x` | `x · x^(x-1)` | `x^x (ln x + 1)` |
| `solve 2^x = 8, x` | `[]` | `3` |
| `solve sqrt(x) = -1, x` | `[1]` | no solution |
| `solve abs(x) = 3, x` | `[x]` | `3, -3` |
| `solve a*x^2 + b*x + c = 0, x` | `[x]` | quadratic formula |
| `solve x^2 - 2*x*y + y^2 = 0, x` | `[0]` | `y` |
| `solve 1/x = 0, x` | `[x]` | no solution |
| `factor x^2 - y^2` | `x · x` | `(x - y)(x + y)` |
| `factor x^2 + 2*x*y + y^2` | `x · x` | `(x + y)^2` |
| `lim 1/x as x->0` | `0` | undefined (±∞) |
| `lim (x^2+1)/(2x^2-3) as x->oo` | `(oo^2 + 1)/(2·oo^2 - 3)` | `1/2` |
| `lim (1 + 1/x)^x as x->oo` | `1/oo + 1^oo` | `e` |
| `det [[1,2],[3,4]]` | `0.0` | `-2` |
| `eval 10^20 + 1 - 10^20` | `0.0` | `1` |
| `solve x^4+x^3+x^2+x+1 = 0` | floats shown as fractions (`416020/1346269`) | exact radicals or `RootOf` |

Causes found in the source:

- **Power rule** (`calculus.rs:114`): `d(u^v) = v·u^(v-1)·u'` only. It
  ignores the exponent's dependence on the variable. The general rule is
  `u^v (v'·ln u + v·u'/u)`.
- **Multivariate factor** drops the second variable instead of refusing.
- **Limits at infinity** substitute `oo` as a symbol.
- **`eval`** is `f64` only, so it loses exactness and prints `2^100` as a
  float with a trailing `.0`. `pi` is an unknown symbol to `eval`.

### 1.3 Commands that report success but compute nothing

In `crates/algebra-engine/src/executor.rs` these arms format their input into
a string and return `OperationResult::success`:

- `det` (hard-coded `0.0 (Symbolic Matrix Evaluated)`), `inv`, `trace`,
  `transpose`, `charpoly`, matrix multiply. Real implementations exist in
  `matrix.rs` (`determinant`, `inverse`, `charpoly`) and are not called.
- `discriminant` (prints `[Evaluated]`), `resultant`, `poly_gcd`.
- `sum` (echoes the sum), `ilt` (echoes), `fourier` (restates the integral).
- `truth_table` (prints `Generated`).
- `sat`: `!formula.contains("not (A or not A)")`.
- `galois` solvability: true unless the group's name contains `s5` or `a5`.

A wrong `success` is worse than an error: callers (the notebook, the JSON
API, an AI agent using the CLI) cannot tell it apart from a real result.

### 1.4 Things that silently do nothing

- `simplify` leaves `sin(x)^2 + cos(x)^2`, `(x^2-1)/(x-1)`, `x/x`,
  `log(exp(x))`, `(2*x)/2`, `1/(1/x)`, `sin(0)`, `log(1)`, `i^2`, `sqrt(8)`
  and `(x+y)^2 - x^2 - 2xy - y^2` unchanged. The e-graph rule set
  (`simplify/mod.rs:295`) is 11 rules: identities, commutativity,
  associativity. Constant folding and like-term collection work
  (`2x + 3x → 5x`, `x^2·x^3 → x^5`).
- `expand (x+1)^5` and `(x+y)^3` are not expanded; products are distributed
  but not collected.
- `factor` returns the input for `x^6 - 1`, `x^4 + 4`, `(x-1)^3` expanded,
  `x^5 + x + 1`.
- `series` is structurally right but unsimplified:
  `exp(0)·0^0 + exp(0)·0^0·x^1 + …) / x^0`.
- Definite integrals print the antiderivative with `along [a, b]` and never
  evaluate; `∫ 1/x` over `[-1, 1]` is not flagged as divergent.
- `integrate` fails on `1/x^2`, `x/(x^2+1)`, `1/(x(x+1))`,
  `1/(x^2+2x+5)`, `sin(x)^2`, `sin(x)cos(x)`, `log(x)`, `sqrt(1-x^2)`.
- The JSON API returned `integral_latex: null` with `success: true` when
  `compute_integral` was set, and computes a derivative when none was asked.

### 1.5 Parser gaps

No implicit multiplication (`2x`, `(1+2)(3+4)`), no `!`, no `%`, no
two-argument `log(x, 2)`. Of the limit forms the operation table lists, only
`lim f as x->a` parses; `limit f, x, a`, `limit of … as x approaches …` and
`lim_{x->0}` fail. `sum k, k, 1, n` fails. `gcd`, `is_prime` and
`prime_factors` take integer literals only, not expressions like `2^67 - 1`.

### 1.6 What is correct

Rational arithmetic; polynomial solving to degree 4 with complex roots;
`RootOf` for the quintic; Lambert W for `x·e^x = 1`; product, quotient and
chain rules for fixed exponents; integration by parts (`x^2 sin x`,
`x e^x`); `∫ e^(-x^2) = (√π/2) erf(x)`; partial fractions; `together`;
`L{sin t}`; L'Hôpital-type limits (`sin x / x`, `(1 - cos x)/x^2`,
`(sin x - x)/x^3`, `x log x`); extended gcd with Bézout coefficients;
factorial, binomial, Catalan, Stirling, Bell and partition numbers in exact
big integers (`p(1000)` and `p(10000)` checked); continued fractions; prime
factorisation with Gaussian/Eisenstein annotations for 64-bit inputs.

## 2. Tests

- 675 tests pass in a few seconds; the main suite's 319 run in 2.2 s.
- None of the failures above has a test. The one determinant test
  (`tests/core/operation_tests.rs:107`) checks that `det [[1,2],[3,4]]`
  *parses*, not that it equals −2. Some tests assert only that something
  exists (`assert!(!graph.is_empty()); assert_ne!(disc, a);`).
- The new `tests/fixtures/reference_oracles.json` with
  `scripts/gen_reference_fixtures.py` is the right idea: known values
  generated offline and checked in CI. It currently covers Stirling, Bell,
  tensor canonicalisation and transform samples.
- The README badge says "480+ Passing"; the workspace now has 675.

## 3. Efficiency

- Symbolic operations are fast: a REPL run of 53 commands takes 88 ms
  including process start, so each is well under a millisecond.
  `5000!`, `C(10000, 5000)` and `p(10000)` are instant.
- **Integer factoring is trial division** (`numbertheory.rs:123`, `:297`):
  17 s to report that the 63-bit prime 9223372036854775783 is prime, 3 s for
  a 60-bit semiprime. Miller–Rabin (deterministic for 64-bit) plus Pollard
  rho does both in microseconds. `d * d <= n` can also overflow for `n`
  near 2^64. Inputs above 64 bits are rejected, although big integers are
  already available.
- The e-graph runner is capped at 15 000 nodes, 30 iterations and 250 ms,
  which is sensible, but with 11 rules it has little to do.
- `eval` being `f64` is fast but gives up the exactness the rest of the
  engine has.

## 4. Flexibility

Good: one `MathOperation` type parsed once and executed centrally, used by
the CLI, JSON API, notebook, kernel, WASM, LSP, FFI and Python layers; arena
DAG with interned symbols; domain and goal-domain configuration; step traces
and Lean/Coq export hooks; code generation to Rust and Python.

Limits: the executor passes matrices, polynomials and formulas around as
strings (`matrix_str`, `poly_str`), which is why several arms can only echo;
there is no assumptions system (`sqrt(x^2)` cannot become `|x|` or `x`);
the parser's command grammar is ad hoc per command.

Breadth is far ahead of depth: about 100 000 lines across 19 crates, with
modules for exceptional Lie algebras, p-adic Hodge theory, CFT, QFT and
PINNs, while `simplify sin(x)^2 + cos(x)^2` does not work.

## 5. Historical Capability Baseline (at `23f508b`)

| Capability | Status at `23f508b` | Key Gaps Observed |
|---|---|---|
| Arithmetic, rationals, big integers | Good | Exact `BigUint` / `BigInt` / rational arithmetic supported |
| Simplification (trig, rational, radical) | Weak (11 rules) | Lacks general trig, rational cancellation, exp/log, and domain-aware rules |
| Expand / factor | Limited | Univariate quadratics only; lacks general multivariate factoring |
| Differentiation | Partial defects | Wrong for variable exponents (power rule defect at `23f508b`) |
| Integration | Narrow | No definite integration in executor; narrow Risch coverage |
| Equation solving | Partial | Polynomials to degree 4; errors on transcendental/general forms |
| Limits, series, sums | Limited | L'Hôpital cases only; unsimplified series; symbolic summation incomplete |
| Linear algebra | Disconnected in executor | Underlying `matrix.rs` implemented, placeholder arms in executor |
| Number theory | Good to 64-bit | Slow integer factoring; 64-bit ceiling in high-level paths |
| Speed & deployment | Strong | Fast Rust core across native desktop/CLI/Python/FFI and WASM |
| Plotting / graphing & steps | Partial | Visualization/step hooks exist; GUI/WASM paths unaudited at `23f508b` |

URAE's core architectural strengths — runtime performance, a single Rust core targeting both native and WASM, and exact combinatorics — only deliver value when core CAS outputs are verified correct across every path.

## 6. Recommended order of work

1. **Fix the formatter** with operator precedence in all three printers, and
   print subtraction and negative terms properly. Add round-trip tests:
   `parse(format(e)) == e`.
2. **Remove the placeholder arms**: wire `det`, `inv`, `trace`, `transpose`,
   `charpoly`, matrix multiply to `matrix.rs`; implement or return an error
   for `discriminant`, `resultant`, `poly_gcd`, `sum`, `ilt`, `truth_table`,
   `sat`, `galois`. Never return `success` without a computed value.
3. **Fix the wrong answers** in 1.2, starting with the power rule, then the
   solver cases, multivariate factor and limits at infinity.
4. **Grow the oracle fixtures** to cover differentiation, integration
   (verify by differentiating the result), solving (verify by substitution),
   factor/expand (verify by re-expansion), limits and simplification (several
   hundred curated reference cases, e.g., via `scripts/gen_reference_fixtures.py`).
   This is the regression gate needed to catch executor/CAS regressions automatically.
5. **Simplifier rules**: trig identities, rational cancellation, exp/log,
   powers, known function values, with an assumptions system for the
   domain-sensitive ones.
6. **Exact `eval`** (rationals and big integers first, floats on request),
   with `pi` and `e` as constants.
7. **Number theory**: Miller–Rabin and Pollard rho; lift the 64-bit limit.
8. **Parser**: implicit multiplication, `!`, the comma forms of `limit` and
   `sum`, expressions as integer arguments.
9. Hold new advanced modules until the items above pass the oracle suite.
