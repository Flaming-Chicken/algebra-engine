### C. Oversimplifications

Status on 18 Nov 2026 (merged through PR #95): every item below has been examined against the code and
most are fixed. What remains open or only partly fixed:

- **C3**: Collins projection (CAD) still uses the simplified operator. Everything else in C3 is done: all 2-D
  constraint kinds, points in 3-D and N-D, lines and planes in space, circle radii as unknowns.
- **C9**: `MctsPolicyHead` scores with rule-logit heuristics instead of the loaded model (needs the weights).
- **C15**: the LSP completion catalogue is a hand-written list; no central function registry exists to generate it.
- **D1**: screws, and any CAD mesh without a prismatic stack, still use the surface `Tri3` pseudo-stiffness in 3-D
  (gears, wings and springs are real tetrahedral solids).
- **A5/A8**: Gosper's algorithm, closed-form polynomial x geometric sums and recurrence guessing exist, but
  Zeilberger's creative telescoping (the proof certificate) does not.
- **C4/C5** have only minor remainders (other drive types and head shapes; codifferential and Laplacian for
  non-Euclidean metrics).

The entries below record what was checked and changed for each item.

- **C2 Fixed.** `RittWuReducer::reduce` is Ritt's differential pseudo-division (derivatives of the leader eliminated highest first using the matching derivative of the divisor, then algebraic pseudo-division by the leader); `characteristic_set` is Ritt's procedure (autoreduced subset, reduce the rest, repeat) and no longer just sorts its input. `DiffPolynomial` gained normalisation and arithmetic, and `differentiate` merges repeated indeterminates (it used to leave `y'` twice in a term). Two existing tests pinned the stub: `{y'', y, y'}` has characteristic set `{y}`, not the three polynomials.
- **C11 Fixed.** Weyl-operator and differential-polynomial conversions no longer lose information silently: `weyl_to_diff_polynomial` returns an error for an operator with an `x` power or several variables, and `TryFrom<DiffPolynomial> for WeylDOperator` accepts only terms linear in one indeterminate (so `y·y'` and `(y')²` are rejected). Linear constant-coefficient operators round-trip exactly.
- **C15 Partly fixed.** LSP hover now evaluates the lines above the cursor first, so earlier definitions are in scope (it evaluated the hovered line alone), and `completions_at` offers names defined above the cursor ahead of the catalogue. Still open: the catalogue itself is a hand-written list, not generated from a central function registry (none exists).
- **C6 Fixed.** `AdjointSensitivitySolver::compute_gradient` is the discrete adjoint of the RK4 forward pass: it recomputes each step's four stages and back-propagates through them, so it returns the exact gradient of the numerical trajectory (it previously ignored the vector field and used a first-order backward Euler on the continuous adjoint, an O(h) error against a fourth-order forward solve). Checked against the analytic gradient with fourth-order convergence and against central finite differences of the discrete solver on a coupled nonlinear system (agreement 1e-8).
- **C1 Fixed.** `IgaStiffnessMatrix::integrate_stiffness_entry_2d` computes the Laplace–Beltrami stiffness `∫ ∇R_a·∇R_b dΩ` from the analytic NURBS derivatives (`NurbsPatchND::rational_basis`, `tangents`) and the surface metric, with Gauss–Legendre quadrature on every knot span (it used a weight of 1.0 on the diagonal and 0.1 off it); `assemble_2d` builds the full matrix, and `metric_determinant_2d` uses analytic tangents instead of forward differences. Verified: the unit-square Q1 matrix (2/3, −1/6, −1/3), invariance under scaling and tilting into 3D, rectangle aspect ratio, row sums zero, and the energy `xᵀKx` of a rational quarter annulus equals its exact area `3π/4` to 1e-9.
- **C13 Fixed (as clarified).** `CodeGenerator::compile_fn1/2/n` compile to bytecode once and run the VM per call (they cloned the graph and substituted into the tree on every call), fall back to the tree evaluator when the VM cannot compile, and return `NaN` for an unbound symbol or too few arguments; the VM compiler reports an unbound symbol instead of reading it as the variable. `RiemannSurface::sqrt_surface_with` takes a `RiemannHeight` (`Real`, `Imaginary`, `Modulus`). `algebra_advanced::gpu` is documented for what it is, multi-threaded CPU kernels (no SIMD intrinsics, no GPU): `GpuComputeKernel::enabled` now really selects the parallel or the sequential path (it was ignored), and `SimdPolyVector` gained `checked_add` / `checked_multiply` because the existing methods wrap on `i64` overflow. `GpuKernelDescriptor::validate` structurally checks generated WGSL (balanced delimiters, `@compute fn main`, workgroup size within the default 256-invocation limit and matching the descriptor, unique bindings, enough buffers); it is not a WGSL compiler, and nothing creates a GPU device or dispatches work. Real SIMD and WebGPU execution are a feature, not a defect, and are now documented as absent.
- **C5 Partly fixed.** `DifferentialForm` keeps `f64` coefficients, so its exterior derivative can only be zero. New `cartan_symbolic::SymbolicForm` holds each coefficient as an expression in the coordinate symbols and implements `d`, wedge, sum, scaling, interior product and the Lie derivative (Cartan's formula `L_X = i_X d + d i_X`). Verified by numerical evaluation at sample points: `d(f)` and the curl components of a 1-form, `d(dw) = 0` for non-trivial coefficients, the Leibniz rule `d(a^b) = da^b - a^db`, anticommutativity and `a^a = 0`, `i_X i_X = 0`, and `L_X` of the rotation-invariant `x^2 + y^2` and of `dx`. `SymbolicForm::parse` reads `sin(x) dx^dy - (y+1) dz` (whitespace between coefficient factors multiplies: `x^2 y dx`, `2 x y dz`, `(x+1) (y-1) dy`) and `to_text` simplifies each coefficient; `MathOperation::Cartan` now falls back to it when a form has non-numeric coefficients, so `d(x^2*y dx)` works in a notebook (constant-coefficient output is unchanged; a bare word is now a symbolic 0-form and a mistyped `dq` is rejected). `SymbolicForm` also has the Hodge star (matching the constant implementation on constant forms, Euclidean and Minkowski sign convention), the codifferential `(-1)^(n(k+1)+1) * d *` (minus the divergence on 1-forms) and the Laplace-de Rham operator (minus the Laplacian on functions, componentwise on flat 1-forms). `CartanOpKind::{InteriorProductSymbolic, LieDerivativeSymbolic}` take a vector field whose components are expression strings (`["y", "-x"]`, `["x^2", "0"]`), parsed in the coordinates and applied by `SymbolicForm`; the numeric-vector variants are unchanged (rotation leaves `x^2 + y^2` invariant, `i_X(dx^dy)` for the rotation field, a non-constant field; unreadable components and a field of the wrong length are errors). Still open: (a non-diagonal metric is covered by `hodge_star_metric`, below). `SymbolicForm::hodge_star_diagonal` now takes a diagonal metric whose entries are expressions (`sqrt|det g| * prod 1/g_ii * sign(I,J)`): in spherical coordinates `star dr = r^2 sin(theta) dtheta^dphi`, `star dtheta = -sin(theta) dr^dphi`, `star dphi = dr^dtheta / sin(theta)` and `star 1 = r^2 sin(theta) dr^dtheta^dphi`, `star star = +1`, and `diag(1,1,1,1)` / `diag(-1,1,1,1)` reproduce the flat and Minkowski `hodge_star`. `SymbolicForm::hodge_star_metric` takes a full symmetric metric `g_ij(x)` (up to four coordinates; inverse by adjugate, raised components from minors of the inverse), agreeing with the diagonal version on diagonal metrics for every degree and satisfying `omega ^ star omega = <omega, omega>_g vol` and `star star = +1` for a constant non-diagonal metric and a position-dependent one; the notebook operation `CartanOpKind::HodgeStarMatrix` takes the full matrix as expression strings. The notebook operation `CartanOpKind::HodgeStarMetric` takes a diagonal metric as expression strings (`["1", "x^2", "x^2*sin(y)^2"]`).
- **C10 Partly fixed.** The FEA linear solve no longer skips a singular equation and returns zero for it: a pivot that is round-off relative to its own row is an error ("under-constrained"), and the solution is checked against the original system (relative residual 1e-6). This exposed a test that fixed only one translation of a box and had been passing on zeros. Systems above 400 unknowns are now solved from CSR storage by Jacobi-preconditioned conjugate gradients (`CsrMatrix`, stopping on the componentwise backward error, which penalty rows cannot mask; an indefinite or under-constrained matrix is an error). Dirichlet constraints (fixed displacements, prescribed temperatures) are now eliminated exactly instead of penalised, and `FeaSolution::reaction_forces` is filled (it was always zero). Assembly is now sparse too (`SparseAssembly`, row maps; the constrained system is built from it directly and large ones go to CSR conjugate gradients, so no dense matrix is formed above 400 free unknowns; a 1681-unknown plate solves in milliseconds). C10's solver and assembly work is complete; the element formulations are covered by D1.
- **The D series.** Items D1 to D4 were not in the original catalogue (A1-A11, B1-B12, C1-C15): they are defects found by the audits made while working through it, numbered separately so they cannot be confused with the catalogue's C11 to C15.
- **D1 (found in the FEA stress audit) Fixed for 2-D and Tet4.** The plane-strain constitutive matrix was wrong (`C11 = E/((1+v)(1-2v))`, `C12` divided by `1-v`, shear modulus `(1-v)/2` of that), and the per-element von Mises stress was built from absolute values of nodal differences (`|u1-u0| + |u2-u0|`), which is not a strain at all. Stress is now `C B u` for the constant-strain triangle with the correct plane-stress and plane-strain matrices (plane strain includes `sigma_z = v (sigma_x + sigma_y)`), checked by a uniaxial patch test that CSTs reproduce exactly (stress, von Mises and the lateral contraction `-v eps y`, or `v/(1-v)` in plane strain). Linear tetrahedra (`ElementType::Tet4`, `FeaMesh::box_3d`) are now a real 3-D solid element (isotropic Lame constitutive matrix, full von Mises, body force), verified by an exact uniaxial patch test (stress, displacement field and the support reaction `sigma*A`). Body force was also ignored for 2-D triangles and is now applied (the support reaction of a hanging plate equals its weight); an element type the elasticity solver does not implement (`Quad4`, `Tri6`, `Hex8`, ...) is now an error instead of being silently skipped. Bilinear quadrilaterals (`Quad4`, `FeaMesh::plate_2d_quad`, 2x2 Gauss) are implemented too and pass the constant-strain patch test exactly on a distorted mesh in plane stress and plane strain (an inverted element is an error). Still open: the 3-D `Tri3` surface element keeps its diagonal pseudo-stiffness (no shell formulation); trilinear hexahedra (`Hex8`, `FeaMesh::box_3d_hex`, 2x2x2 Gauss) are implemented for elasticity and heat and pass exact patch tests on a distorted mesh (an inverted element is an error); quadratic triangles (`Tri6`, `FeaMesh::plate_2d_tri6`, straight-sided; a curved midside node is an error) reproduce quadratic solutions exactly in elasticity (a hanging plate with `nu = 0` matches `-g(H^2-y^2)/2E` at every node, the support reaction equals the weight) and heat (`q x (L-x)/2k`), and pass the uniaxial patch tests; quadratic tetrahedra (`Tet10`, `FeaMesh::box_3d_tet10`, straight-sided, 4-point Gauss) are implemented for elasticity and heat and exact on quadratic solutions (a block hanging under its weight with `nu = 0`, the support reaction equals the weight; a source slab) plus the uniaxial patch test. Heat conduction now covers Quad4 and Tet4 as well as Line2 and Tri3 (linear-field patch tests exact on distorted quadrilaterals and on tetrahedra; a uniform-source slab peaks at `qL^2/8k` within 3%), and an element type without a heat formulation is an error instead of being skipped.
- **D2 (found building the gear solid mesh) Fixed.** The gear end-cap triangulation (angular merge of the toothed outline with the bore ring) emitted one *folded* triangle per radial root segment on small pinions (12 of them on a 12-tooth gear): an outline edge that is nearly radial has the axis almost on its line, so a bore vertex angularly behind it lies on the wrong side. The folds cancelled in the signed volume, so every volume test passed. The merge now checks the orientation of the candidate triangles and advances the bore first when the angular rule would fold; a new test requires every cap triangle of involute, cycloidal and internal gears to have the correct orientation. Built on that, `CadFeaBridge::gear_to_fea` now meshes a bored gear as a real **solid** of linear tetrahedra (cap triangles extruded through the layers, each prism cut into three tetrahedra with the index-sorted diagonal rule; FEA nodes are the CAD vertices; tetrahedra volumes sum exactly to the solid's volume; bore reactions balance the tooth load), so the pipeline's gear analysis is real 3-D elasticity rather than the surface pseudo-stiffness. Limits: a gear without a bore and a strongly twisted helical gear (or any twisted gear with radial root segments, i.e. fewer than about 42 teeth) keep the surface fallback, because the stacked prisms would fold; airfoils are now solids too (the centroid-fan section cap is extruded through the 8 spanwise sections by the same shared prism stacker; the FEA nodes are the CAD vertices plus one centroid node per interior section; tetrahedra volumes equal the wing's volume, a clamped wing under a tip load deflects towards the load, more towards the tip, and the root reactions balance it; a twisted wing is a solid as well because rotated sections never fold). Springs are solids too (`CadFeaBridge::spring_to_fea`, groups `spring_bottom` / `spring_top`): the wire's circular cross-section (a fan around the ring centre) is swept along the helix by the same prism stacker, with an orientation guard that uses the triangle normal along the path since the rings are not planar-parallel; tetrahedra volumes agree with the closed mesh to 3%, deflection is linear in the load, the clamp carries the whole load, and the axial stiffness is 1.5 to 3 times the coil formula `G d^4 / (8 D^3 n)` (linear tetrahedra over an 8-element wire are too stiff in torsion, so it is an upper bound). Only screws still use the surface mesh (ledger D1): the helical thread is a height field in polar angle, not a prismatic stack.
- **D3 (found auditing mesh orientation) Fixed.** `Mesh3D::compute_volume` returns an absolute value, so a mesh whose normals point *into* the solid passes every closure and volume check. The new `signed_volume` / `is_outward_oriented` (and `reverse_orientation`) exposed three builders that were inside out: `NacaAirfoil`, `HelicalSpring` and `Mesh3D::cube`. All three now have outward normals; one test requires every CAD builder (involute, helical, cycloidal and internal gears, airfoils, spring, hex, socket, chamfered and lead screws, cube, extrusions in both windings, an implicit sphere) to be closed and outward-oriented with `signed_volume == compute_volume`. The earlier statement that the airfoil and spring were 'closed, outward-oriented' (C4) was only half verified: they were closed and consistently oriented, but inward.
- **D4 (found reading `gear_to_fea`) Fixed.** The `bore_hole` and `teeth_flanks` boundary groups were chosen by fractions of the radial range (`r - r_min <= 0.35 span`, `r_max - r <= 0.45 span`): `teeth_flanks` was in effect the whole outline (it included the tooth roots) and `bore_hole` could swallow outline vertices when the bore was large. They are now selected by geometry: `bore_hole` is exactly the bore-cylinder vertices (2 x 48 on a bored two-layer gear, none without a bore) and `teeth_flanks` the outline vertices above the pitch circle; a test checks both on three gears.
- **C14 e-graph Fixed.** `cat-egraph`: `add` hash-conses (an existing node returns its class), `rebuild` restores congruence closure (`a = b` merges `f(a)` and `f(b)`, upward to a fixed point) and runs after every saturation round, `extract_min_cost` returns the *total* cost of the cheapest expression (it scored a node by its operator and operand count only, ignoring the operands' own cost), and `extract_term` builds the cheapest tree, computed by a fixed-point over classes so cyclic classes (`x = x + 0`) extract their finite form. With this C14 is complete: unification, wavefront and the e-graph.
- **C14 wavefront Fixed.** `WavefrontSchedule::build` assigns levels by dependency (Kahn's algorithm) so edge listing order no longer matters, and reports cycles; `evaluate` returns a `Result`, evaluates `Add`, `Mul`, `Neg`, `Inv` and `Identity`, and reports a missing wire, an unsupported operation or division by zero instead of substituting `0`. 
- **C14 unification Fixed.** `UnificationEngine::unify` is first-order Martelli–Montanari: structural decomposition of functions, operators and arithmetic nodes, an occurs check, and a most general unifier whose `apply` makes both sides equal. It is syntactic (no commutativity). The CLI proof export no longer uses unification to gate steps; it records the simplification only when the equivalence check confirms it.
